# Changelog

Curated notable changes and incident narrative. Newest first.

## 2026-08-18

- **Both components of a pair now carry their own doors** (maintainer-caught, then maintainer-decided). The dev-container had been built with no published ports, and its Quadlet cited the objective's Security outcome 1 as the reason — for the opposite of what that line says, since it names hardened SSH/MOSH on **both components** as the only public doors and the dev-container is a component rather than one of the "everything else" services confined to private networks. The maintainer then settled the wider question: both components are tailnet nodes, each with its own Tailscale SSH, so the tailnet ACL can reach the dev-container without reaching the host that operates it. Ports are load-bearing rather than arbitrary — mosh maps one-to-one because mosh-server advertises the port it picked, and starts above 61000 because the host's own mosh holds the 60000-61000 default on the same address. He also noted this should be stated in the objective; that is a charter amendment and his to confirm. See docs/decisions/000030.
- **A narrow consult of `fedora-dev`, and what it corrected.** ADR 000027 recorded the prior fleet as out of scope entirely. Two questions then arose that the exclusion could not answer — whether a distrobox assembles inside a rootless container, and how to publish a container's doors without colliding with the host's — and the author flagged the first as untested and likely broken rather than shipping it quietly. The maintainer narrowed the exclusion to those two named, already-working points. The nesting works and needs five specific declarations, one of which caught a live defect: subordinate ID ranges here were sized to the host-side habit and could not fit inside the outer rootless map, so the first box assemble would have failed. The fleet's architecture stays out of scope; consulting it for a measured operating fact is not the same act as taking its shape back. See docs/decisions/000031 and 000029.
- **The agent box's nesting cost is written down, including the one real relaxation.** `SecurityLabelDisable=true` is required because nested rootless podman plus fuse-overlayfs plus the passed devices cannot run under `container_t`. It is the only line in the pair that weakens a host-level protection, and it is recorded with its boundary — every capability is held inside an unprivileged user namespace and the host stays enforcing — rather than left as an unexplained flag someone later tidies away. See docs/decisions/000029.
- **The Tailscale provenance gap narrowed, closing something already intended.** ADR 000027 and the map both recorded that the signing key was unpinned and that the first session with upstream reach should pin it. The consult supplied a better mechanism than the one planned: pin the sha256 of the vendor's own `.repo` file, so the definition is Tailscale's rather than our transcription of it and a changed `baseurl` or `gpgkey` URL stops the run. It is not a key-fingerprint pin and the disclosure says so — the residue is a key substituted at the pinned URL, bounded by TLS and by `gpgcheck` thereafter. C4 already required the strongest form a source admits, so this is compliance rather than amendment; the bylaw's own Fedora L2 wording describes the weaker form and is recommended for sharpening.
- **The strix lineage exists as code** (issue #11), and building it corrected the lineage that came first. Strix is the smaller ticket because its host image is already built and working, so there is no host build at all — what was missing was the adapter, the pair's second component, and the activation act. `host/activate.sh` is the bare-metal track's day zero and it installs nothing: that track's host state arrives by image rebase, so a package installed there would be the mutable out-of-band change C7 forbids. It confirms what the image baked, takes the same single approval erebus takes, reads the vault for the two things an image may never hold, and retires root under the same guard. Which converger units apply is now a track fact the adapter declares, so each track's sanctioned deploy mechanism stays sole owner of what it owns. See docs/specs/000011-strix-genesis.
- **One dev-container image now serves every lineage**, and the erebus work is corrected in the same change rather than worked around. Issue #10 had shipped `ghcr.io/oso-gato/nox`, a `nox-session` entrypoint, a `nox` command and a per-pair Quadlet — four pair-specific names for things that are not pair-specific, and a second pair would have had to fork all four. The image is `ghcr.io/oso-gato/dev-container`, the entrypoint `pair-session`, the Quadlet a template rendered per pair, and the enter command one file that takes its container from its own invocation name. `nox` and `moros` now differ in exactly two facts, both adapter values. A known-wrong name that ships is harder to remove than one that never did, and both tickets sit on one unmerged branch. See docs/decisions/000028.
- **The adapter rule became a checked fact rather than an aspiration.** The self-test renders the shared Quadlet template against every adapter and requires a complete unit from each, requires every adapter to declare the full variable set the units read, and fails if any unit or library branches on a pair name — so `strix.env` is provably the only file outside documentation that mentions strix. That last check needed repair before it could be trusted: its first version matched the `if` inside `verify` and fired on a comment, which is the guard-reporting-an-unjustifiable-finding failure the constitution's own preamble names, appearing inside the mechanism written to prevent it.
- **A prerequisite is stated rather than left to surface at apply time.** The strix pair's two GitHub Apps do not exist — the registry lists both as planned — and creating one is an act on github.com that no artifact can perform. The adapter carries their names with empty IDs and activation treats that as a warned, non-fatal state: the host joins the tailnet and runs its dev-container, and the boxes hold no GitHub authority until the maintainer creates the Apps and re-runs. Making it fatal was rejected, because it would block two working outcomes on a prerequisite unrelated to either.
- **The erebus lineage exists as code** (issue #10). Day zero, the idempotent converger, the agent box and the `nox` dev-container, delivered to the boundary the maintainer set: the artifact he pastes, never applied by its author. The build order is his and is now on record — erebus is lineage 1 and goes first because the VPS is the more stable surface, and strix follows because it carries more load and full virtualization. Day zero splits at the one human act: everything before the GitHub device-flow approval runs from public sources, and everything after it reads the estate vault for the three values a public repository may never hold. The converger's units are idempotent by reading live state rather than by consulting a sentinel, which is what makes a second apply's silence mean something. Root retires only once `core` is provably usable, because locking it earlier would strand the host with no way back in — the human summons C11 forbids. Proven at tier 1: 59 checks pass, including the idempotence primitives exercised against a real filesystem and mutation-checked so the check is shown able to fail. Tier 2 is the apply, and it is his. See docs/specs/000010-erebus-genesis and docs/decisions/000026.
- **Two facts that lived in no repository are recorded.** `oso-gato/strix-ms-s1-bootc` is a **donor** — read from and adapted, never forked, never depended on at run time — and it is why the strix ticket is the smaller one: that host's image is already built and working, so lineage 2's remaining work is `moros` and the activation act. The prior fleet (`noir-strix-halo-fcos`, `fedora-dev`, `fedora-bootstrap`) is out of scope entirely, stated in writing because availability reads as sanction to the next agent and that fleet's audit is recent enough that its code still looks current. Two donations were taken and both changed on the way in: the `claudebox` layer and its session lock came across close to verbatim because C8 is the same law on both tracks, while the App-token minter and the key sync were made pair-neutral and repointed at the estate vault, since the donor's own credential repository predates ADR 000011. See docs/decisions/000027.
- **A provenance gap is open and named rather than papered over.** The session that built erebus could not reach `quay.io`, `pkgs.tailscale.com` or `downloads.claude.ai` — the environment's network policy answered 403 to all three — so no donor-verified fact was re-checked live and the trail records the donor's dates rather than borrowing today's. The artifact verifies at fetch time on the host instead, fail-closed: signing keys are pinned to disk before anything installs and a declared fingerprint that does not match stops the run. Tailscale's fingerprint is unpinned, because the estate's last verified position on it pins none and inventing one would be worse than declaring the gap; the first session with upstream reach should pin it.
- **Maintainer act, on record: the charter re-anchored and the prior epoch removed.** `chartered-2026-08-18-0159` is planted on `c5bded5` and the floating `chartered` moved onto it, so the named restore point is once again the confirmed charter rather than a state nine commits behind it. `chartered-2026-08-17-2032` and its Release are deleted on maintainer instruction; the epoch ruleset was stood down for the deletion and re-armed immediately after, and its active state was verified. The removed epoch's commits remain in git history, unnamed. This is the second deliberate exception to the never-delete conduct, made for the same reason as the first — the removed epoch was a same-day state superseded by the amendments above it. The conduct stands unchanged: no agent moves or deletes an epoch, and the floating name is maintainer-movable by its own ruleset.
- **A track is not a lineage, and four sentences redrawn** (maintainer-confirmed, wording chosen by him from drafted alternatives). `lineage` meant a host-named pair in the objective and a deploy-mechanism family in the bylaw; a second cloud host would have split the senses while tickets stamp per pair, the registry holds one file per host, and the mechanism is defined per bylaw-lineage. The estate already had the right word two paragraphs away, so the bylaw now says a host belongs to one of two **tracks**, and the objective's host bullet follows its track's deploy mechanism. Four sentences in the objective were rewritten into short prose with every element preserved and each shown before and after; the one genuine ambiguity — what the trailing clause in Confirmation attached to — was settled as the constitution joining the other two as the charter's third file. Two defects that propagate were closed: the genesis skeleton still shipped the label-colon register into every future charter, and AGENTS.md regains "For structural work", dropped without record when the charter widened. See docs/decisions/000025.
- The independent audit behind that record returned its verdict on the charter as a whole, and it was not critical: the construct is sound, every structural measurement reproduced under a second set of instruments, and the two co-created files meet the standard set for them. Its own adversarial pass killed nine findings and rejected six proposed rewrites for losing meaning, one of which silently deleted a live obligation from the sentence it was repairing.
